# ИИ в чате ПроРельс

В `/admin/chats` у выбранной переписки появилась панель ИИ: предварительный ответ, серверный таймер 7 секунд, отмена с перехватом человеком и повторное включение ИИ. Таймер также виден в списке переписок. Ручной ответ менеджера выключает ИИ в этой переписке.

Посетитель открывает чат кнопкой в правом нижнем углу сайта. Черновиков у него нет; отправленные ответы подписаны «ИИ-консультант ПроРельс». Обычные ответы менеджера и непрочитанные сообщения работают как раньше.

Нужен backend с миграцией `20261113090000_chat_ai` и событиями `chat:ai`, `chat:ai:mode`, `chat:ai:cancel`. Ключ и флаг подключения задаются **только в backend**, см. его `CHAT_AI.md`. Без ключа панель показывает «ИИ ещё не подключён», обычный чат доступен. Развёртывать backend и frontend до включения `CHAT_AI_ENABLED=true`.

## Проверки

- `npm run build`, `npm run lint`, `npm test`.
- Backend: отдельная локальная PostgreSQL `*_test`, `node test/chat-ai-server.cjs` (тестовая подмена провайдера, порт 4191). Frontend: локальный сервер на 4173 с прокси к нему.
- `CHAT_TEST_AI=true PLAYWRIGHT_CHANNEL=chrome npx playwright test test/chat-ai.e2e.spec.ts` — два браузерных контекста: черновик только в админке, отмена, ожидание без отправки, включение, автоматическая отправка и ручной перехват; проверка desktop и mobile.
- `npx playwright test test/chat.e2e.spec.ts test/chat-preview.e2e.spec.ts` — обычный WebSocket-чат, повторное подключение, SSR каталога, обработка пустого ответа API и cookies в мобильном preview.

Без `CHAT_TEST_AI=true` тест ИИ пропускается. Все браузерные тесты ограничены loopback-адресом. Реальный ответ GigaChat и боевой nginx требуют отдельной проверки после подключения ключа и развёртывания.
